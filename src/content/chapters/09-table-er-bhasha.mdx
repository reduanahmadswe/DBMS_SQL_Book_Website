## সমস্যাটা আসলে কী

রিলেশনাল মডেলের ভাষা গণিত থেকে এসেছে (Codd, সেট-তত্ত্বের ভিত্তিতে)। ভাষাটা না জানলে পরবর্তী অধ্যায় — key, constraint, algebra — বোঝা কঠিন। এই অধ্যায়ে পরিভাষা ও relation-এর বৈশিষ্ট্য একদম পরিষ্কার করব।

## কদম চাচার ক্লাস

### পরিভাষা — দুই নামের তালিকা

| আনুষ্ঠানিক (formal) | সাধারণ (informal) | উদাহরণ |
|---|---|---|
| **Relation** | টেবিল | `customers` |
| **Tuple** | সারি / রেকর্ড | রহিম উদ্দিনের পুরো সারি |
| **Attribute** | কলাম / ফিল্ড | `phone` |
| **Domain** | কলামের বৈধ মানের সেট | `status ∈ {PENDING, SHIPPED, DELIVERED, CANCELLED}` |
| **Degree (arity)** | কলাম সংখ্যা | `customers`-এ ৭ |
| **Cardinality** | সারি সংখ্যা | `customers`-এ ২০ |
| **Relation schema** | টেবিলের নকশা | `customers(customer_id, name, phone, …)` |
| **Relation instance** | টেবিলের বর্তমান ডাটা | এই মুহূর্তের ২০টি সারি |

একটি টেবিলের বিভিন্ন অংশ এক ঝলকে (একটি `riders` টেবিল):

### Relation Schema ও Instance

গাণিতিকভাবে: relation schema `R(A₁, A₂, …, Aₙ)`, প্রতিটি `Aᵢ`-র domain `dom(Aᵢ)`। Relation `r(R)` হলো `dom(A₁) × … × dom(Aₙ)`-এর একটি **উপসেট** — অর্থাৎ বৈধ মান-সমন্বয়ের কিছু অংশ, যেগুলো ডাটাবেসে আছে।

### Relation-এর বৈশিষ্ট্য

১. **Tuple-এর ক্রম গুরুত্বহীন** — সেটের মতো; সারি যেকোনো ক্রমে থাকলেও relation একই।
২. **Attribute-এর ক্রম** গুরুত্বহীন (নাম-ভিত্তিক সংজ্ঞায়)।
৩. **ডুপ্লিকেট tuple নেই** — relation একটি সেট।
৪. **প্রতিটি attribute-নাম অনন্য** relation-এর ভেতরে।
৫. **প্রতিটি ঘরের মান atomic** — একাধিক মান নয় (এটাই 1NF)। Multi-valued ও composite মান নিষিদ্ধ।
৬. **NULL** অনুমোদিত (যদি constraint বাধা না দেয়)।

<Callout type="warning" title="Relation আর SQL টেবিল পুরোপুরি এক নয়">
গাণিতিক relation সেট, তাই ডুপ্লিকেট নেই। কিন্তু SQL টেবিল (primary key না থাকলে) ডুপ্লিকেট সারি রাখতে পারে — তাকে **bag (multiset)** বলে। এজন্যই SQL-এ `DISTINCT` আছে। পরীক্ষায় "relation-এ ডুপ্লিকেট থাকে না" লিখবে; বাস্তবে SQL-এ PK দিয়ে তা নিশ্চিত করতে হয়।
</Callout>

### ডাটাবেস স্কিমা

একাধিক relation schema + integrity constraint মিলে **relational database schema**। লেদু মার্ট: ১১টি relation schema।

## টেকনিক্যাল গভীরে

### Domain ও Atomicity

Domain হতে পারে built-in type (INTEGER, TEXT, DATE) বা সংজ্ঞায়িত সেট। একটি মান **atomic** — রিলেশনাল মডেলের কাছে অবিভাজ্য। `"০১৭১…, ০১৮১…"` একটি ঘরে দুই নম্বর রাখলে atomicity ভাঙে।

### NULL-এর বিশেষ অর্থ

NULL domain-এর মান নয়; "মান নেই/অজানা"। NULL = NULL সত্য নয় (তিন-মান যুক্তি, অধ্যায় ১৭)।

### কোডের ভাষায় Degree ও Cardinality

SQL-এ কোনো কলামের নাম/সংখ্যাকে `PRAGMA table_info` (SQLite) বা `information_schema.columns` (MySQL/PostgreSQL) দিয়ে পাওয়া যায়। সারি গোনা `COUNT(*)`।

## হাতে-কলমে

`customers`-এর **degree** (কলাম সংখ্যা) — `PRAGMA table_info` প্রতিটি কলামের জন্য একটি সারি দেয়:

<SqlRunner initialQuery={`PRAGMA table_info(customers);`} expectRows={7} minRows={1} />

সাতটি সারি = degree ৭। এবার **cardinality** আর কলামের **domain**-এর বাস্তব মান:

<SqlRunner initialQuery={`SELECT COUNT(*) AS cardinality FROM customers;`} expectRows={1} minRows={1} />

<SqlRunner initialQuery={`SELECT DISTINCT city FROM customers ORDER BY city;`} expectRows={4} minRows={1} />

`city` কলামে বর্তমানে ৪টি মান আছে — কিন্তু domain এর চেয়ে বড় (যেকোনো শহরের নাম)। Instance সবসময় domain-এর উপসেট।

- **"Relation মানে দুই টেবিলের সম্পর্ক"** — না; relation = একটি টেবিল।
- **Degree ও cardinality উল্টে ফেলা** — degree = কলাম, cardinality = সারি।
- **সারির ক্রমের উপর নির্ভর করা** — `ORDER BY` ছাড়া ক্রম গ্যারান্টিহীন।
- **একটি ঘরে একাধিক মান রাখা**।

## পরীক্ষার টিপস

<Callout type="exam">
**লিখিত:** পরিভাষার (relation/tuple/attribute/domain/degree/cardinality) সংজ্ঞা + relation-এর বৈশিষ্ট্য। **গণনা:** R(A,B,C) ও ৫টি সারি → degree ৩, cardinality ৫। **ট্র্যাপ:** (১) Cartesian product-এ degree যোগ, cardinality গুণ। (২) "Relation schema vs instance"। (৩) relation = সেট, তাই ডুপ্লিকেট নেই (SQL bag ছাড়া)।
</Callout>

<Summary>
- Relation = টেবিল; tuple = সারি; attribute = কলাম; domain = বৈধ মানের সেট।
- Degree = কলাম সংখ্যা; cardinality = সারি সংখ্যা। Schema = নকশা; instance = বর্তমান ডাটা।
- বৈশিষ্ট্য: tuple/attribute-ক্রম গুরুত্বহীন, ডুপ্লিকেট tuple নেই, atomic মান, অনন্য attribute-নাম।
- SQL টেবিল = bag (PK ছাড়া ডুপ্লিকেট সম্ভব), relation = সেট।
</Summary>

<Answer>
`|dom(A) × dom(B)| = 2 × 3 = 6`। Relation এই গুণফলের উপসেট এবং সেট বলে ডুপ্লিকেট নেই, তাই সর্বোচ্চ ৬টি tuple।
</Answer>
</Exercise>

</Answer>
