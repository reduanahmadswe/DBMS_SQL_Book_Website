লেদু মার্টের কাস্টমার তালিকায় দুজন "রহিম উদ্দিন", একজন সাভারের, একজন মিরপুরের। অ্যাপে "রহিম উদ্দিনের বাকি দেখাও" বলতেই কোন রহিমের হিসাব আসবে? লেদু হিমশিম। কদম চাচা বললেন, "লেদু বাপজান, নাম দিয়ে মানুষ চেনা যায় না। এমন একটা জিনিস দরকার যা কখনো রিপিট করে না, একটা চাবি।"

## সমস্যাটা আসলে কী

রিলেশনাল মডেলে ডাটা সারির সমষ্টি। একটি সারিকে নির্ভুলভাবে খুঁজে পেতে ও অন্য টেবিল থেকে তাকে refer করতে key দরকার। Key-এর নানা প্রকার, প্রতিটির ভূমিকা আলাদা।

## কদম চাচার ক্লাস

### Super Key

<KeyTerm en="Super Key" bn="সুপার কি">এক বা একাধিক attribute-এর সেট, যার মান দিয়ে relation-এর প্রতিটি tuple অনন্যভাবে চেনা যায়</KeyTerm>, বাড়তি attribute থাকলেও সমস্যা নেই।

`customers(customer_id, name, phone, city, …)`: ধরি `customer_id` ও `phone` দুটোই unique। তাহলে super key: `{customer_id}`, `{phone}`, `{customer_id, name}`, `{phone, city}`, `{customer_id, phone, city}`…। শুধু `{name}` বা `{city}` নয়, দুই রহিম।

### Candidate Key

<KeyTerm en="Candidate Key" bn="ক্যান্ডিডেট কি">ন্যূনতম (minimal) super key, এর কোনো প্রকৃত উপসেট আর super key নয়</KeyTerm>। `{customer_id}` ও `{phone}` দুটোই candidate key; `{customer_id, name}` নয়, কারণ `name` বাদ দিলেও থাকে।

### Primary Key

Candidate key-গুলোর মধ্য থেকে ডিজাইনারের বাছাই করা একটি। নিয়ম: NULL নয়, অনন্য, সাধারণত ছোট ও অপরিবর্তনীয়। প্রতি টেবিলে একটিই।

### Alternate Key

বাছাই-না-হওয়া বাকি candidate key, `customers.phone` (UNIQUE NOT NULL হিসেবে)।

### Foreign Key

<KeyTerm en="Foreign Key" bn="ফরেন কি">এক টেবিলের এক বা একাধিক attribute, যা অন্য (বা একই) টেবিলের primary/candidate key-কে refer করে</KeyTerm>। মান হয় NULL, নয়তো রেফারকৃত টেবিলে থাকা মান। `orders.customer_id → customers.customer_id`।

### Composite Key

একাধিক attribute মিলে গঠিত key, `order_items(order_id, product_id)`। কোনো একটি একা unique নয়, জোড়াটি unique।

### Surrogate Key

<KeyTerm en="Surrogate Key" bn="সারোগেট কি">ব্যবসায়িক অর্থহীন, সিস্টেম-তৈরি কৃত্রিম আইডি (যেমন auto-increment)</KeyTerm>। বিপরীতে **natural key** বাস্তব জগতের অর্থযুক্ত (NID, ফোন)। `customer_id` একটি surrogate key।

### Unique Key (UNIQUE constraint)

যেকোনো কলাম/সেটে ডুপ্লিকেট নিষেধ। Primary key-র সাথে পার্থক্য: UNIQUE একাধিক থাকতে পারে, এবং (SQL স্ট্যান্ডার্ড, MySQL, PostgreSQL, SQLite-এ) NULL রাখা যায়; SQL Server-এ একটিমাত্র NULL চলে।

## টেকনিক্যাল গভীরে

### Key নির্ধারণের নিয়ম

Key হলো স্কিমার বৈশিষ্ট্য (ডিজাইনের সিদ্ধান্ত), বর্তমান ডাটার নয়। এখন কোনো কলামে ডুপ্লিকেট না থাকলেই সেটি key নয়; কারণ ভবিষ্যতে ঢুকতে পারে। অর্থ ও ব্যবসায়িক নিয়ম দেখে key ঠিক হয়।

### Super key গণনা

R-এ n টি attribute এবং শুধু একটি candidate key A (একটি attribute) হলে super key = A যুক্ত যেকোনো উপসেট = `2^(n−1)`। R(A,B,C) → ৪।

### Natural না Surrogate?

Natural key (NID, ISBN) অর্থবহ কিন্তু বদলে যেতে পারে/ভুল হতে পারে এবং বড় হতে পারে। Surrogate ছোট, স্থির, join-এ দ্রুত। বাস্তবে প্রায়ই surrogate PK + natural alternate key (UNIQUE)। আমাদের `customers`: `customer_id` (surrogate PK) + `phone` (UNIQUE)।

### Foreign key-র নিয়ম

- FK ও PK-র domain সামঞ্জস্যপূর্ণ।
- FK NULL হতে পারে (অংশগ্রহণ ঐচ্ছিক হলে)।
- FK একই টেবিলকেও refer করতে পারে (`employees.manager_id`)।
- Composite PK-কে refer করলে FK-ও composite।

## হাতে-কলমে

কোন কলাম candidate key হতে পারে, ডাটা দেখে বোঝার প্রথম ধাপ: মোট সারি বনাম ভিন্ন মান।

<SqlRunner initialQuery={`SELECT COUNT(*)                AS total,
       COUNT(DISTINCT phone)   AS distinct_phone,
       COUNT(DISTINCT name)    AS distinct_name,
       COUNT(DISTINCT city)    AS distinct_city
FROM customers;`} expectRows={1} minRows={5} />

`phone`-এ ২০/২০ (সব ভিন্ন), candidate-এর যোগ্য; `city`-তে মাত্র ৪, কখনোই নয়। (মনে রাখো: এটা শুধু ইঙ্গিত; চূড়ান্ত সিদ্ধান্ত ব্যবসায়িক নিয়মে।)

Alternate key `phone` কাজ করছে, ডুপ্লিকেট ফোন ঢোকানোর চেষ্টা:

<SqlRunner initialQuery={`INSERT INTO customers (name, phone, city, joined_on)

Composite key `(order_id, product_id)`, একই পণ্য একই অর্ডারে দ্বিতীয়বার সারি হিসেবে ঢোকানো যাবে না (পরিমাণ বাড়াতে হলে আপডেট করো):

## পরীক্ষার টিপস

<Callout type="exam">
লিখিত: সব key-র সংজ্ঞা ও উদাহরণ; super vs candidate; PK vs UNIQUE। গণনা: "R(A,B,C,D)-তে candidate key AB হলে super key কয়টি?" → AB যুক্ত উপসেট = `2^(4−2) = 4`। (বহু candidate key থাকলে inclusion-exclusion; অধ্যায় ২৯-এ FD দিয়ে key বের করা শিখব।) MCQ ট্র্যাপ: (১) প্রতি টেবিলে PK একটিই, candidate key একাধিক। (২) FK-এ ডুপ্লিকেট চলে।
</Callout>

<Summary>
- **Super key** = অনন্যভাবে চেনায় এমন attribute-সেট; **Candidate key** = ন্যূনতম super key।
- **Primary key** = বাছাই করা candidate (NOT NULL, অনন্য); বাকিরা **alternate key**।
- **Foreign key** = অন্য টেবিলের key-র রেফারেন্স; **Composite key** = একাধিক attribute; **Surrogate key** = কৃত্রিম আইডি।
- UNIQUE একাধিক হতে পারে, NULL (বেশিরভাগ DBMS-এ) চলে; PK-তে NULL নয়।
</Summary>
