## সমস্যাটা আসলে কী

অ্যাপের কোডে যাচাই করলেও বাইরে থেকে (স্ক্রিপ্ট, অন্য অ্যাপ, ফটকা!) ডাটা ঢুকতে পারে। শেষ প্রতিরক্ষা তাই ডাটাবেসেই। <KeyTerm en="Integrity Constraint" bn="ইন্টিগ্রিটি কনস্ট্রেইন্ট">ডাটাবেসের ডাটা সঠিক ও সঙ্গতিপূর্ণ রাখতে প্রতিটি অবস্থায় যে নিয়ম মানতেই হবে</KeyTerm>।

## কদম চাচার ক্লাস

### চার ধরনের মূল integrity

১. **Domain constraint:** প্রতিটি attribute-এর মান তার domain-এর ভেতরে (type, পরিসর, বিন্যাস)। SQL: data type, `NOT NULL`, `CHECK`, `DEFAULT`।

২. **Key constraint:** প্রতিটি relation-এ কমপক্ষে একটি key; key-র মান অনন্য। SQL: `PRIMARY KEY`, `UNIQUE`।

৩. **Entity integrity:** **Primary key-র কোনো অংশই NULL হতে পারবে না**। (NULL মানে "অজানা"; অজানা দিয়ে সারি চেনা যায় না।)

৪. **Referential integrity:** Foreign key-র মান হয় NULL, নয়তো রেফারকৃত টেবিলে বিদ্যমান key-র সমান। কোনো "ঝুলন্ত" (dangling) রেফারেন্স থাকবে না। SQL: `FOREIGN KEY … REFERENCES`।

(এর বাইরে *semantic* বা ব্যবসায়িক নিয়ম — "রাইডার একসাথে ১০টির বেশি অর্ডার পাবে না" — trigger/assertion দিয়ে।)

### SQL Constraint-এর তালিকা

| Constraint | কাজ | উদাহরণ |
|---|---|---|
| `NOT NULL` | NULL নিষেধ | `name TEXT NOT NULL` |
| `UNIQUE` | মান অনন্য | `phone TEXT UNIQUE` |
| `PRIMARY KEY` | NOT NULL + UNIQUE, একটি | `customer_id INTEGER PRIMARY KEY` |
| `FOREIGN KEY` | রেফারেন্স বৈধ | `REFERENCES customers(customer_id)` |
| `CHECK` | শর্ত | `CHECK (price > 0)` |
| `DEFAULT` | উহ্য থাকলে ডিফল্ট | `stock INTEGER DEFAULT 0` |

### Referential Action: parent বদলালে child-এর কী হবে?

Parent-এর সারি মুছলে (ON DELETE) বা key বদলালে (ON UPDATE), child-এর জন্য বিকল্প:

| Action | অর্থ |
|---|---|
| **CASCADE** | child-ও মুছে যাবে/বদলাবে |
| **SET NULL** | child-এর FK = NULL (FK কলাম NOT NULL না হলে) |
| **SET DEFAULT** | child-এর FK = ডিফল্ট মান |
| **RESTRICT** | child থাকলে অপারেশন সঙ্গে সঙ্গে প্রত্যাখ্যান |
| **NO ACTION** | (ডিফল্ট) যাচাই statement/transaction শেষে; ভাঙলে প্রত্যাখ্যান |

## টেকনিক্যাল গভীরে

### কোন অপারেশন কোন constraint ভাঙতে পারে?

| অপারেশন | ভাঙতে পারে |
|---|---|
| **INSERT** | domain, key (ডুপ্লিকেট), entity (PK NULL), referential (FK-র মান নেই) |
| **DELETE** | শুধু referential (অন্য টেবিলের FK এটিকে refer করলে) |
| **UPDATE** | যে attribute বদলায় তার উপর নির্ভর করে — PK/FK বদলালে key/entity/referential; সাধারণ attribute বদলালে domain |

এটি পরীক্ষার প্রিয় প্রশ্ন: **DELETE কেবল referential integrity ভাঙতে পারে।**

### Constraint-এর নাম দেওয়া

বড় সিস্টেমে constraint-এর নাম দিলে error পড়া ও পরে `ALTER` করা সহজ:

```sql
CREATE TABLE payments (
  payment_id INTEGER PRIMARY KEY,
  order_id   INTEGER NOT NULL,
  amount     INTEGER NOT NULL,
  CONSTRAINT fk_payment_order FOREIGN KEY (order_id) REFERENCES orders(order_id),
  CONSTRAINT ck_amount_positive CHECK (amount > 0)
);
```

### Deferred constraint

Transaction-এর শেষে যাচাই (DEFERRABLE INITIALLY DEFERRED) — PostgreSQL, SQLite সমর্থন করে; দুটি টেবিল পরস্পরকে refer করলে দরকার।

<Callout type="note" title="SQLite-এ Foreign key চালু করতে হয়">
SQLite-এ foreign key যাচাই ডিফল্টে বন্ধ থাকে; `PRAGMA foreign_keys = ON;` লাগে। আমাদের প্লেগ্রাউন্ডে এটি আগে থেকেই চালু। MySQL (InnoDB) ও PostgreSQL-এ সবসময় চালু।
</Callout>

## হাতে-কলমে

**NOT NULL:** নাম ছাড়া কাস্টমার ঢোকানো যাবে না:

<SqlRunner initialQuery={`INSERT INTO customers (name, phone, city, joined_on)
VALUES (NULL, '01999999999', 'ঢাকা', '2024-11-01');`} expectError minRows={3} />

**Referential integrity (RESTRICT/NO ACTION আচরণ):** যে পণ্য কোনো অর্ডারে আছে তা মোছা যাবে না:

<SqlRunner initialQuery={`DELETE FROM products WHERE product_id = 1;`} expectError minRows={1} />

**DEFAULT:** `stock` না দিলে ০ বসে:

<SqlRunner initialQuery={`INSERT INTO products (name, category_id, supplier_id, price, unit)
VALUES ('নতুন পণ্য', 1, 1, 10, 'পিস');

SELECT name, stock FROM products WHERE name = 'নতুন পণ্য';`} expectRows={1} minRows={4} />

**CASCADE ও SET NULL একসাথে:** নিজস্ব ছোট টেবিলে দেখি। পণ্য মুছলে রিভিউ মুছে যাবে (CASCADE), ব্র্যান্ড মুছলে পণ্যের ব্র্যান্ড NULL হবে (SET NULL):

<SqlRunner initialQuery={`CREATE TABLE brand (brand_id INTEGER PRIMARY KEY, name TEXT);
CREATE TABLE item (
  item_id INTEGER PRIMARY KEY, name TEXT,
  brand_id INTEGER REFERENCES brand(brand_id) ON DELETE SET NULL);
CREATE TABLE review (
  review_id INTEGER PRIMARY KEY,
  item_id INTEGER NOT NULL REFERENCES item(item_id) ON DELETE CASCADE,
  stars INTEGER CHECK (stars BETWEEN 1 AND 5));

INSERT INTO brand VALUES (1, 'পদ্মা');
INSERT INTO item VALUES (1, 'সয়াবিন তেল', 1), (2, 'সরিষার তেল', 1);
INSERT INTO review VALUES (1, 1, 5), (2, 1, 4), (3, 2, 3);

DELETE FROM item WHERE item_id = 1;      -- review 1, 2 মুছে যাবে (CASCADE)
DELETE FROM brand WHERE brand_id = 1;    -- item 2-এর brand_id NULL হবে (SET NULL)

SELECT (SELECT COUNT(*) FROM review) AS reviews_left,
       (SELECT brand_id FROM item WHERE item_id = 2) AS item2_brand;`} expectRows={1} minRows={20} />

ফলাফল: `reviews_left = 1`, `item2_brand = NULL`।

## ফটকার ভুল

Constraint দিলে ডাটাবেস ধীর হয়। আমি সব বন্ধ রাখি, অ্যাপে চেক করি!
</Dialogue>

<Dialogue who="kodom">
ফটকা, অ্যাপ চেক করে, কিন্তু ডাটা তো অ্যাপ ছাড়াও ঢোকে। একটা পুরনো স্ক্রিপ্ট, একটা ভুল ইম্পোর্ট — ব্যস, গোটা ডাটাবেস দূষিত। constraint-এর খরচ সামান্য, দূষিত ডাটার খরচ অসীম।
</Dialogue>

- **ভাবা যে অ্যাপে যাচাই-ই যথেষ্ট**।
- **`ON DELETE CASCADE` সবখানে দেওয়া** — একটি ভুল DELETE চেইনে অনেক ডাটা মুছে ফেলতে পারে। আর্থিক রেকর্ডে (payments) সাধারণত RESTRICT বা soft delete।
- **PK NULL হতে পারে ভাবা** (বিশেষত composite-এ)।
- **DELETE-এ key/domain ভাঙার কথা বলা** — DELETE শুধু referential।
- **SQLite-এ `PRAGMA foreign_keys` ভুলে যাওয়া**।

## পরীক্ষার টিপস

<Callout type="exam">
**লিখিত:** চার ধরনের integrity + উদাহরণ; ON DELETE/UPDATE অ্যাকশন; "INSERT/DELETE/UPDATE কোন constraint ভাঙতে পারে" টেবিল (এটি প্রায় প্রতি বছর আসে)। **MCQ ট্র্যাপ:** (১) Entity integrity = PK NOT NULL। (২) Referential = FK মিলতে হবে। (৩) DELETE → শুধু referential। (৪) CHECK = domain/semantic।
</Callout>

<Summary>
- Integrity constraint = ডাটা সঠিক রাখার ডাটাবেস-স্তরের নিয়ম।
- চার মূল: domain, key, entity (PK NOT NULL), referential (FK বৈধ)।
- SQL: NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK, DEFAULT।
- Referential action: CASCADE, SET NULL, SET DEFAULT, RESTRICT, NO ACTION।
- INSERT সব ভাঙতে পারে; DELETE শুধু referential।
</Summary>
