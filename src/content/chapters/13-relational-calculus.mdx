## সমস্যাটা আসলে কী

Relational algebra বলে *কোন ধাপে* ফল তৈরি হবে (procedural)। Relational calculus বলে *ফল কেমন হবে* (declarative), শুধু শর্ত (predicate)। দুটোর ক্ষমতা সমান; SQL-এর মূল ভাবনা এখান থেকেই।

## কদম চাচার ক্লাস

### Tuple Relational Calculus (TRC)

সাধারণ রূপ: `{ t | P(t) }`, "সব tuple `t` যাদের জন্য predicate `P(t)` সত্য।" `t` একটি tuple variable; `t ∈ R` মানে t, relation R-এর একটি tuple; `t.A` মানে A attribute-এর মান।

উদাহরণ ১: ৫০০-র বেশি দামের পণ্য:

`{ t | t ∈ products ∧ t.price > 500 }`

উদাহরণ ২: শুধু নাম ও দাম (কিছু attribute চাইলে):

`{ t.name, t.price | t ∈ products ∧ t.price > 500 }`

### Quantifier: ∃ ও ∀

- `∃ s (s ∈ R ∧ …)`, "অন্তত একটি tuple আছে যার জন্য…"।
- `∀ s (s ∈ R → …)`, "R-এর প্রতিটি tuple-এর জন্য…"। `∀x P ≡ ¬∃x ¬P`।

উদাহরণ ৩ (∃): যে কাস্টমার অন্তত একটি অর্ডার দিয়েছে:

`{ c | c ∈ customers ∧ ∃ o (o ∈ orders ∧ o.customer_id = c.customer_id) }`

উদাহরণ ৪ (¬∃): যারা কখনো অর্ডার দেয়নি:

`{ c | c ∈ customers ∧ ¬∃ o (o ∈ orders ∧ o.customer_id = c.customer_id) }`

### Domain Relational Calculus (DRC)

Variable tuple নয়, প্রতিটি attribute-এর domain-এর মান: `{ <x₁, x₂, …, xₙ> | P(x₁, …, xₙ) }`।

উদাহরণ ৫: ৫০০-র বেশি দামের পণ্যের নাম ও দাম:

`{ <n, p> | ∃ id, c, s, st, u ( <id, n, c, s, p, st, u> ∈ products ∧ p > 500 ) }`

অর্থাৎ products-এর সাত attribute-এর জন্য সাতটি variable; যেগুলো চাই না সেগুলো ∃ দিয়ে বাঁধা।

### Safe Expression

`{ t | ¬(t ∈ products) }`, "যা products-এ নেই এমন সব tuple", অসীম ফল (সব সম্ভাব্য tuple)! এমন unsafe expression-কে নিষিদ্ধ করা হয়। Safe expression-এর ফল সবসময় সসীম এবং তার মান আসে ডাটাবেসে থাকা মান থেকে। Codd-এর উপপাদ্য: safe TRC, safe DRC ও relational algebra সমান ক্ষমতার (relationally complete)।

## টেকনিক্যাল গভীরে: Calculus বনাম Algebra বনাম SQL

| | Relational Algebra | Relational Calculus | SQL |
|---|---|---|---|
| ধরন | Procedural | Declarative | Declarative (+ কিছু procedural এক্সটেনশন) |
| বলে | ধাপগুলো | কেমন ফল চাই | কেমন ফল চাই |
| ভিত্তি | সেট-তত্ত্ব | predicate logic | TRC + bag semantics |
| ডুপ্লিকেট | নেই (সেট) | নেই | আছে (`DISTINCT` লাগে) |

### Calculus → SQL ছক

| Calculus | SQL |
|---|---|
| `t ∈ R` | `FROM R t` |
| `t.A > c` | `WHERE t.A > c` |
| `∃ s (s ∈ S ∧ …)` | `EXISTS (SELECT 1 FROM S s WHERE …)` |
| `¬∃ …` | `NOT EXISTS (…)` |
| `∀ s (…)` | `NOT EXISTS (… NOT EXISTS …)` |
| `∧ / ∨ / ¬` | `AND / OR / NOT` |

## হাতে-কলমে

উদাহরণ ৩ (∃), অন্তত একটি অর্ডার দিয়েছে এমন কাস্টমার:

<SqlRunner initialQuery={`SELECT c.name
FROM customers c
WHERE EXISTS (
  SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id
);`} expectRows={13} minRows={5} />

উদাহরণ ৪ (¬∃), যারা কখনো অর্ডার দেয়নি:

<SqlRunner initialQuery={`SELECT c.name
FROM customers c
WHERE NOT EXISTS (
  SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id
);`} expectRows={7} minRows={5} />

১৩ + ৭ = ২০ জন কাস্টমার, দুটো কোয়েরি একে অপরের পরিপূরক।

∀ ধরনের প্রশ্ন: "যে পণ্য *প্রতিটি* স্টোরের অন্তত একটি অর্ডারে আছে", ডাবল `NOT EXISTS`:

<SqlRunner initialQuery={`SELECT p.name
FROM products p
WHERE NOT EXISTS (
  SELECT 1 FROM stores s
  WHERE NOT EXISTS (
    SELECT 1
    FROM order_items oi
    JOIN orders o ON o.order_id = oi.order_id
    WHERE oi.product_id = p.product_id AND o.store_id = s.store_id
  )
);`} minRows={13} />

(কোনো পণ্যই সব স্টোরে বিক্রি না হলে ফল ফাঁকা, সেটাও বৈধ উত্তর।)

## পরীক্ষার টিপস

<Callout type="exam">
লিখিত: TRC/DRC-তে কোয়েরি লেখা ও algebra/SQL-এ রূপান্তর; safe expression ব্যাখ্যা; algebra বনাম calculus তুলনা (টেবিল)। MCQ ট্র্যাপ: (১) TRC variable = tuple; DRC variable = domain-এর মান। (২) ∀ = ¬∃¬। (৩) Calculus declarative, algebra procedural। (৪) Relationally complete = algebra-র সমান ক্ষমতা।
</Callout>

<Summary>
- Calculus = declarative; শুধু ফলের শর্ত (predicate) বলে।
- **TRC** `{ t | P(t) }`, tuple variable; **DRC** `{ <x₁…xₙ> | P }`, domain variable।
- ∃ ও ∀ কোয়ান্টিফায়ার; `∀x P ≡ ¬∃x ¬P`।
- Safe expression-এর ফল সসীম; safe calculus ≡ relational algebra (Codd)।
- SQL: `EXISTS`/`NOT EXISTS` দিয়ে ∃/∀।
</Summary>
